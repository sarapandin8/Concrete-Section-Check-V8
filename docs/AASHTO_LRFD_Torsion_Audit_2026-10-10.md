# รายงานตรวจสอบ Concrete Section Pro — IGIRDER.TORSIONAUDIT12

วันที่ 10 ตุลาคม 2026 · ตรวจจาก IGIRDER.MAXMIN10 · AASHTO LRFD 9th Edition, 2020 ตามเอกสารที่ผู้ใช้ให้

## ผลที่พบและการแก้ไข

พบความเผื่อเพิ่มสองจุดที่อธิบายได้ว่าทำไมแอปแสดงกำลังบิดต่ำและอัตราส่วนตรวจสอบ Shear + Torsion สูงกว่าการแทนค่าตรงตามวิธี General Procedure:

1. MAXMIN10 ใช้ `Veff × dv` เป็นโมเมนต์ขั้นต่ำในสมการ longitudinal strain ทั้งที่นิยาม Mu ในข้อ 5.7.3.4.2 ยังคงกำหนดขั้นต่ำด้วย **แรงเฉือนจริง `|Vu − Vp| × dv`** การแทน Vu ด้วย Veff ใช้กับพจน์แรงเฉือนในสมการ 5.7.3.4.2-4 การใช้ Veff ซ้ำในขั้นต่ำ Mu ทำให้ εs และ θ สูงขึ้นและลด Tn ผ่าน cotθ โดยเฉพาะกรณี Tu สูงและ Mu ต่ำ
2. MAXMIN10 ใช้ `Veff / [φ(0.25 f′c bv dv + Vp)]` เป็นองค์ประกอบ D/C และทำให้ FAIL ได้ แอปเรียกเกณฑ์นี้ว่า additional conservative guard อยู่แล้ว แต่รวมผลไว้กับองค์ประกอบกำลัง ข้อ 5.7.3.3-2 กำหนดขีดจำกัดกำลังเฉือนด้วย Vu จริง ส่วนข้อ 5.7.3.4.2-5 ให้ Veff สำหรับการหาค่า strain ไม่ได้สั่งให้แทน Veff ในสมการขีดจำกัดนี้

**ข้อควรตีความ:** หน้า 5-72 อนุญาตให้เลือก εs สูงกว่าค่าที่คำนวณได้ภายในขีดจำกัด ดังนั้นวิธีเดิมในจุดที่ 1 เป็นความเผื่อเพิ่มที่ code ยอมให้เลือก ไม่ใช่หลักฐานว่า MAXMIN10 ผิด AASHTO โดยอัตโนมัติ ฉบับนี้เปลี่ยนเป็นการแทนค่าตรงตามนิยามและแสดงที่มาของ Mu ขั้นต่ำใน Calculation trace

ฉบับ TORSIONAUDIT12 ใช้ Vu จริงในขั้นต่ำ Mu และใน D/C ของขีดจำกัดกำลังเฉือน แต่ **ยังคงเกณฑ์ Veff เพิ่มไว้เป็น REVIEW** หากอัตราส่วนเกิน 1.0 เกณฑ์เพิ่มนี้ไม่ถูกรวมใน code-component D/C และไม่อนุญาตให้ยอมรับหน้าตัดเป็น PASS โดยอัตโนมัติ การขาดกำลังเหล็กปลอก เหล็กตามยาว หรือกำลังเฉือนจริงยังคงเป็น FAIL

## หน้าตัดที่ใช้

คงฐานหน้าตัดของ MAXMIN10: ใช้การทำงาน composite ใน de/dv และแรงดึง–แรงอัดสำหรับ final composite shear/strain โดยใช้ bv และ f′c ของ web คาน ส่วน Ao/ph ของแรงบิดยังอ้างอิงรูปทรง girder และวงเหล็กปลอกที่โมเดลประกาศไว้ ไม่มีการเพิ่ม effective deck width เข้า Ao เพื่อให้กำลังสูงขึ้น

การใช้ deck ในกำลังบิดทั้งระบบต้องยืนยัน shear-flow path, เหล็กปิดวง เหล็กตามยาว และการถ่ายแรงผ่าน interface จริง ไม่สามารถตัดสินจากคำว่า “composite” หรือจากชื่อ Beam/Girder output ของ CSI อย่างเดียว ฉบับนี้จึงยังเป็นการตรวจ girder torsion cage ภายใต้ฐาน composite strain ของแอป ไม่ใช่การรับรองแรงบิดของระบบ girder–deck ทั้งหมด

## ตัวอย่างอิสระสำหรับยืนยันผล

ใช้ **หน้าตัดและแรงสมมติ** ไม่ใช่ข้อมูลคานของผู้ใช้: girder รูป I มี haunch สูง 1,600 mm, web 200 mm, f′c = 45 MPa; deck กว้าง effective 2,400 mm หนา 220 mm, f′c = 35 MPa; strands 20 เส้น Aps รวม 2,800 mm² ที่ y = 120 mm; เหล็กตามยาว 4DB20; เหล็กปลอกปิดวง 2 ขา DB16 @ 100 mm, fy = 390 MPa, cover 40 mm และ φ = 0.90

จุดกลางช่วง x = 10 m ของคานยาว 20 m ใช้ strands ที่ถ่าย/พัฒนาแรงครบ Vp = 0 และ λduct = 1 รูปทรง polygon ครบอยู่ใน QA script และ Project JSON ตัวอย่างภายใน ZIP

ค่าที่ใช้ทั้งก่อนและหลังเท่ากัน:

- Acp = 545,000.000 mm²; pc = 5,093.011 mm
- Ao = 283,951.011 mm²; ph = 4,709.011 mm
- dv = 1,601.444 mm; Mu ขั้นต่ำตาม Vu = 300 kN คือ 480.433 kN·m

ตารางต่อไปนี้เป็น **ผลเฉพาะ load station กลางช่วง ด้าน BOTTOM** ทุกแถวมี Vu = 300 kN สถานะในตารางไม่ใช่สถานะยอมรับทั้งคาน:

กรณี Mu = 500, Vu = 300, Tu = 410: θ ลดจาก 42.044° เป็น 29.000° ทำให้ φTn เพิ่มจาก 444.43 เป็น 723.03 kN·m โดย Ao/ph ไม่เปลี่ยน เหล็กปลอกร่วมมี D/C ลดจาก 0.994 เป็น 0.638 แต่ **D/C เหล็กตามยาวเพิ่มจาก 0.416 เป็น 0.634** เพราะ cotθ สูงขึ้น การเพิ่มกำลังบิดจึงไม่ทำให้ทุกองค์ประกอบดีขึ้นเสมอ

กรณี Mu = 2,500, Tu = 450: D/C กำลังเฉือนจริง = 0.093, เหล็กปลอก = 0.878, เหล็กตามยาว = 0.803 แต่เกณฑ์ Veff เพิ่ม = 1.040 จึงยังเป็น REVIEW ไม่ใช่ PASS ส่วน Tu = 500 มี D/C เหล็กปลอก = 1.033 จึงยัง FAIL จริง

**การตรวจตำแหน่งอื่นยังทำงาน:** ตัวอย่าง Mu = 2,500, Tu = 450 มีแถว critical shear section อีกสองแถวที่ FAIL จากเหล็กปลอก/เหล็กตามยาว; D/C สูงสุดของแถวเหล่านั้นประมาณ 1.645 แม้จุดกลางช่วงเป็น REVIEW ฉบับนี้ไม่ซ่อนหรือยกเลิกผลเหล่านั้น กรณี Mu = 0 ยังต้องตรวจด้านอื่นที่แอปสร้างตามกฎเดิม

## การยืนยันผล

1. คำนวณอิสระ 8 กรณี ใช้สมการในหน่วย US ก่อนแปลงกลับ SI เทียบ εs, θ, φTn, D/C เหล็กปลอก, D/C เหล็กตามยาว และขีดจำกัด shear รวมกับพื้นที่/เส้นรอบรูปที่คำนวณจาก polygon และเส้น offset ทางเรขาคณิต: **80 ค่า ผ่านทั้งหมด** คลาดเคลื่อนสัมพัทธ์สูงสุดประมาณ 5.28 × 10⁻¹⁴
2. Scoped regression 62 modules: **821 passed** รวม tests ใหม่สำหรับ Mu floor, ขีดจำกัด shear/Veff แยกกัน, REVIEW/FAIL, geometry deck, Calculation trace และการกัน cached results รุ่นเดิม ไม่ใช่การรันทุก test ใน repository
3. แอป app.py ผ่าน Streamlit AppTest: 2 girders × 2 load cases × 4 checks, Calculate 8 ครั้ง, ไม่มี Streamlit exception, ส่งออก PNG 36 ภาพ ขนาด 2,880 × 1,120 px ทั้ง Max/Min; การเปิดดู/ส่งออกรายงานเรียก solver 0 ครั้งและไม่เปลี่ยน input/cache/design member
4. ตรวจหน้าจอเฉพาะกลางช่วงสองกรณี: additional Veff screen แสดง REVIEW แยกต่างหาก และกำลังเหล็กไม่พอยังคงแสดง FAIL; การตรวจทั้งคานยังเก็บ critical-section FAIL ไว้ ตรวจภาพส่งออกตัวอย่าง Torsion และ Shear + Torsion แล้ว

การแทนค่าอิสระนี้ถือ dv ที่พัฒนาแรงแล้วและ nominal fps จาก trace ของแอปเป็นข้อมูลตั้งต้น ไม่ใช่การตรวจอิสระทุกขั้นของ flexural equilibrium, development หรือระบบโครงสร้างทั้งสะพาน AppTest ใช้ archived CSI vectors กับโมเดลหน้าตัดสมมติสำหรับ QA และไม่ใช่การอนุมัติโครงการจริง

## ขอบเขตที่ยังต้องตรวจด้วยข้อมูลโครงการ

ความเผื่อเดิมที่ยังคงอยู่และอาจทำให้บางกรณีได้กำลังต่ำหรือสถานะ REVIEW:

- การใช้ εs = 0 เมื่อคำนวณได้ค่าลบ และการเพิ่ม εs เมื่อ Nu เป็นแรงดึงโดยยังไม่มีข้อมูลยืนยันจุดเริ่มแตกร้าวที่ด้าน compression
- ระยะปลอกในเส้นทาง I-girder General Procedure ยังใช้ Veff เป็นตัวแทน stress แบบเผื่อเพิ่ม; การแก้ครั้งนี้ไม่ได้เปลี่ยนนโยบายนี้เป็น Vu
- การพัฒนาแรงของ strands/เหล็กตามยาว, fpo ในช่วง transfer, nominal fps แบบเลือกค่าต่ำของกลุ่ม และการใช้ residual hoop area หลังจัดสรรให้ torsion
- K สำหรับ torsion threshold, composite interface, negative composite action, support region และการยืนยันเหล็กปิดวง/เหล็กตามแนว perimeter

ค่ากำลังจริงของคานผู้ใช้ยังสรุปไม่ได้จาก source ZIP อย่างเดียว ต้องใช้ **Project JSON ของ I-girder, load case/station ที่สงสัย และผล Calculation trace/CSV เดิม** เพื่อเทียบ geometry, φ, θ, Ao/ph, steel, development และฐานแรงจาก CSI ที่ตำแหน่งเดียวกัน โดยคงความเกิดพร้อมกันของ Mu, Nu, Vu, Tu
